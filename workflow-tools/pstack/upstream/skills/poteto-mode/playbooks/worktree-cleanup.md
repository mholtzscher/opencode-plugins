### Worktree and simulator cleanup

**OpenCode host adaptation.** Run the packaged script by absolute path. It accepts `--transcripts <export-dir>` before the repo argument for an explicitly supplied project-scoped export. Missing, unreadable, or unmatched activity is `unknown`, so its bucket is `review`. Cross-check active and pinned sessions with the user before treating a candidate as unused. OpenCode session/database storage is not an editor cache. The simulator/cache commands in step 6 apply only to the named macOS tools when present.

1. Snapshot and audit. Record `df -h /`, then run the installed package's absolute `scripts/worktree-audit.sh [-b <pr-base-ref>] [--transcripts <export-dir>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never guessed directory names (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and exported activity, then suggests a bucket. Unknown activity is not inactivity. A slow scan may run in the background through an actual host capability.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every recent or unknown activity row, or anything you doubt, inspect in-scope OpenCode session history through public APIs or supplied exports and ask the user about active/pinned sessions. Subagents can reduce bulky history (principle-guard-the-context-window). Arena and repro worktrees can belong to running children even when no sidebar names them. Hold candidates whose usage cannot be established.
4. Preview the exact candidates and contents. `wip:N` records tracked uncommitted edits; `scratch:N` records untracked files, not proof they are disposable. Inspect tracked, untracked, and ignored files as potentially valuable. Removing a clean worktree may be recoverable from its branch; losing uncommitted files is not. Obtain explicit authorization for irreversible loss and its exact scope. In-use worktrees stay held.
5. Prune only the confirmed, authorized set. Prefer `git worktree remove <path>`. If it refuses because of files, ignored artifacts, or locks, inspect the reason and contents before proceeding. Force removal or deletion of surviving files requires explicit authorization for that exact path and loss; never infer it from a `safe` bucket. Prune registry entries only after verifying the intended directories are gone. Confirm with `df -h /` and re-list; report retained paths and why.
6. Other reclaimers are optional and scoped. Offer simulator cleanup only on macOS with the relevant tools and when the user requested it. Preview simulator/runtime IDs before authorized removal; do not default to deleting all testing devices. Inspect Xcode and package caches only within requested scope. Do not clean Cursor application state or OpenCode databases, sessions, or history. Preserve caches and state the user asked to keep; uncertain contents need a decision.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
